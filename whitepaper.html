Reference Brief / Internet Protocol Version 6

The header, the neighbors, and what abuses both

RFC 8200 (STD 86)40-byte fixed header128-bit addressing IPv6 replaces IPv4's variable-length options with a chain of extension headers, drops the header checksum entirely, and folds ARP, ping, and multicast group management into one protocol, ICMPv6. Neighbor Discovery inherits ARP's total lack of authentication with more moving parts to abuse. This brief covers the fixed header field by field, the Neighbor Discovery message types, the extension header chain, and the attacks/defenses built in this repo, with hover-context on every underlined term.

destination address
128 bits

Address formation

SLAAC: a host builds an address by concatenating a router-advertised prefix with an interface ID, then runs Duplicate Address Detection before using it. See SLAAC.

Interface ID, two ways: EUI-64 derives it deterministically from the MAC (stable forever, trackable forever); privacy extensions generate a pseudo-random one instead, regenerated periodically, specifically to close that tracking gap.

DHCPv6: stateful (server assigns the address), stateless (SLAAC handles the address, DHCPv6 supplies extras), or prefix delegation (a router requests a routed block to hand out on its own LANs) - which mode runs is entirely the RA's M/O flags talking.

MAC 00:1a:2b:3c:4d:5e becomes interface ID 021a:2bff:fe3c:4d5e. The bit flip is backwards from intuition: 0 means "globally unique," and EUI-64 sets it to say exactly that.

Extension header chain

RFC 8200 mandates this order when more than one extension header is present. Every extension header except Fragment shares a generic Next Header + Hdr Ext Len + data shape; ESP breaks even that by putting its Next Header field at the end instead of the front.

# mandated order, RFC 8200 4.1 IPv6 -> Hop-by-Hop(0) -> Destination(60, intermediate) -> Routing(43) -> Fragment(44) -> AH(51) -> ESP(50) -> Destination(60, final) -> upper-layer (TCP/UDP/ICMPv6) # the fragment header is the odd one out: fixed 8 bytes, no Hdr Ext Len Next Header(8) | Reserved(8) | Fragment Offset(13) Res(2) M(1) | Identification(32)

Manipulating this chain - reordering, splitting across fragments, repeating a header - is the main class of IPv6-specific firewall/IDS evasion. See Hop-by-Hop, Routing, and Fragment.

Attacks and defenses in this repo

  1. Rogue RA / SLAAC attack. Advertise a bogus prefix and/or a higher-preference default route. demos/10-attack-lab/01-rogue-ra.py
  2. NDP spoofing. A gratuitous NA with the Override flag set - the direct ARP-spoofing equivalent. demos/10-attack-lab/02-ndp-spoof.py
  3. Fragmentation abuse. Atomic and overlapping fragments, both by hand at the raw-socket level. tools/frag6, demos/10-attack-lab/03-fragmentation-abuse.py
  4. RA flooding. Enough distinct RAs to exhaust a host's default-router/prefix-list processing. demos/10-attack-lab/04-ra-flood.py
  5. NDP visibility. Live-decode RS/RA/NS/NA/Redirect on the wire via an XDP hook. tools/ndp_snoop
  6. The defense. A real RA Guard - walks the extension header chain instead of trusting the fixed header, and drops fragmented ND-shaped traffic instead of reassembling it. tools/xdp_ra_guard

Operations and debugging

  • Classify any address at a glance: sixctl addrs, or by hand - fe80::/10 link-local, fc00::/7 ULA, 2000::/3 GUA, ff00::/8 multicast.
  • Watch NDP live: tcpdump -i eth0 icmp6, or ndp_snoop --iface eth0 for decoded output.
  • Trigger an RA on demand: rdisc6 eth0 from the ndisc6 suite sends an RS and prints the reply.
  • Read the neighbor cache: ip -6 neigh show - the ARP-table equivalent, with real state (INCOMPLETE/REACHABLE/STALE/...).
  • Check what a firewall must never block: NS/NA/RS/RA/Redirect (types 133-137) on-link, or IPv6 itself stops working. RFC 4890 is the reference.

Pitfalls

  • Blocking ICMPv6 wholesale breaks IPv6. There's no ARP, no broadcast, no separate ping protocol underneath it - NDP itself is ICMPv6.
  • NDP has no authentication. Anyone on the link can claim to be a router or claim to own an address. SEND (RFC 3971) fixed this cryptographically in 2005 and essentially nobody deployed it.
  • A naive RA Guard is not a defense. Checking only the unfragmented ICMPv6 type is exactly what RFC 7113 describes being evaded.
  • Privacy addresses aren't a free pass. A host keeps its stable EUI-64 address live for incoming connections alongside rotating temporary ones - both are visible on the wire.
  • Extension header order is a filtering blind spot. A filter keying off Next Header in the fixed header without walking the chain can be bypassed by burying the real upper-layer protocol behind Hop-by-Hop or Destination Options.
